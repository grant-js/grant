A CDM import's password credential now reaches the identities migrated users really have (ADR 0010, Amendment: org-scoped eligibility and conflict handling). Until now an import wrote a password onto an existing identity only when this project's own earlier import had created it, so re-imports skipped almost everyone created by an import before this version or by a sibling project of the same organization. An import may now write onto an identity that is **confined to the importing project's organization**: every active project membership of the user is in a project of that organization, every active organization membership is that organization, there is at least one, and the user does not also sign in with GitHub or Google. An identity this project's own import created stays eligible on its own, and the other guards are unchanged (a verified email method, a credential set in Grant and an absent `password` are never written, deleted or touched). The check is resolved for the whole import in a constant number of queries, not per user.

The credential records the project that wrote it (`providerData.passwordSourceProjectId`; a credential written before this version takes the project that created the identity). The same project sending a different hash replaces it, and an identical hash from any project changes nothing. **Different projects of one organization sending different hashes for the same person is a conflict:** the stored hash is removed and a marker left (`providerData.passwordConflict`), so neither environment's password wins and the outcome does not depend on which project imported first. The user signs in through password reset, which clears the marker (`resetPassword` and `changePassword` now remove it), and every later import skips the row. `SyncProjectResult` gains `passwordsSkippedConflict` and a separate warning for it; the REST `ProjectSyncJob.result` schema now lists all five password counters, which it was missing. A client that reads these counters from the sync job result (grant-etl) should add `passwordsSkippedConflict`.
